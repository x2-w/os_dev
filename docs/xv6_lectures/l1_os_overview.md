# L1:操作系统概述

## 概述

### 什么是操作系统

【用户/内核示意图】

- 硬件：CPU、内存、磁盘、网络等
- 用户应用程序：shell、编译器、数据库等
- 内核服务：文件系统、进程管理、内存管理、网络等
- 系统调用

### 操作系统作用

- 在多个应用程序之间共享硬件资源
- 隔离应用程序，保障安全并限制错误影响范围
- 实现协作应用程序之间的数据共享
- 抽象硬件，提供可移植性和使用便利性

### 操作系统设计权衡

设计上的权衡使操作系统设计变得有趣

- 高效性 vs 抽象性/可移植性/通用性
- 功能强大 vs 接口简洁
- 灵活性 vs 安全性
- 可移植性 vs 利用新硬件和新接口

如果你：

- 对计算系统系统如何工作感到好奇
- 需要排查漏洞或安全问题
- 关注高性能

那么你会庆幸选了这门课程

### 示例1: ex1.c —— 将输入复制到输出

从输入读取字节，并将其写入输出

```bash
% make qemu
$ ex1
```

你可以在网站的课程安排中找到这些示例程序。

- ex1.c 是用 C 语言编写的。
    C 语言可能是操作系统内核中最常用的编程语言。

- read 是系统调用，
    它们看起来像函数调用，但实际上会跳转到内核中执行，同时保持用户空间与内核空间的隔离。

- read()/write() 的第一个参数是“文件描述符”（FD），
    传递给内核以指示它应该读取或写入哪个“已打开的文件”。一个 FD 可以连接到文件、管道、套接字等资源，但该 FD 必须事先被打开过。
    一个进程可以打开多个文件，拥有多个 FD。

- UNIX 的惯例是：FD 0 表示“标准输入”，FD 1 表示“标准输出”。
    程序无需知道输入来自何处，或输出去向何方，
    它们只需读取/写入文件描述符 0 和 1 即可。

- read() 的第二个参数是用于存储读取数据的内存地址，

- read() 的第三个参数是要读取的字节数。
    read() 实际读取的字节数可能少于请求值，但不会多于请求值。

- 返回值：实际读取的字节数，若出错则返回 -1。

- read()/write() 不关心数据的具体格式。
    UNIX I/O 使用 8 位字节，
    数据的解释方式由应用程序决定，例如数据库记录、C 源代码等。

### 示例2：ex2.c —— 创建一个文件

通过open()在磁盘上创建（或打开）一个文件，
    并返回一个文件描述符（若出错则返回 -1）。
文件描述符(FD)是一个小整数，它作为索引，指向内核为每个进程维护的一个表。

```bash
$ ex2
$ cat out
```

不同的进程拥有不同的文件描述符命名空间，
因此文件描述符 3 对不同进程通常代表不同的含义。
这些示例忽略了错误处理——请勿如此粗心！
xv6 书中的图 1.2 列出了系统调用，
或者查看 UNIX 的 man 手册页，例如 `man 2 open`。

当程序调用 open 等系统调用时会发生什么？

看起来像函数调用，但实际上是一条特殊指令。
CPU 会保存一些用户寄存器。
CPU 提升权限级别
CPU 跳转到内核中的一个已知 "入口点"
此时运行的是内核中的 C 代码

内核调用系统调用的具体实现， sys_open() 在文件系统中查找文件名，可能需要等待磁盘操作完成，更新内核的数据结构（如文件块缓存、文件描述符表），恢复用户寄存器，降低特权级别，跳回程序中的调用位置，继续执行。

课程后续会更详细地讲解这些过程。

我一直在使用 UNIX 的命令行界面，即 shell。

shell 显示 "$" 提示符。
shell 是一个普通的用户程序，不属于内核的一部分。
shell 可以让你运行 UNIX 命令行工具，
适用于系统管理、文件操作、开发和脚本编写。

```bash
$ ls
$ ls > out
$ grep x < out
```

UNIX 也支持其他交互方式，
例如图形界面、服务器、路由器等。
但通过 shell 实现的分时操作是 UNIX 最初的重点。

### 示例3：ex3.c —— 创建一个新进程

shell 会为每个你输入的命令创建一个新的进程。
进程是一个正在运行的程序，包含内存、栈和内核状态，与其他进程相互隔离，以防止错误扩散。

`ex3.c`

系统调用 fork() 可以创建一个新进程。
内核会复制调用进程的所有内容，包括指令、数据、寄存器、文件描述符和当前工作目录。
由此产生 "父进程" 和 "子进程"。

[图示：ex3 和子进程]

因此，子进程和父进程在初始时完全相同！

唯一的区别是：fork() 在父进程中返回子进程的 PID，在子进程中返回 0。

PID（进程 ID）是一个整数，内核会为每个进程分配不同的 PID。

```bash
$ ex3
```

因此：

ex3.c 中的 “fork() 返回” 这段代码会在两个进程中都执行。

通过 "if(pid == 0)" 判断当前是父进程还是子进程。

fork() 之后，父子进程都会继续运行。

好的，现在我们能用 fork() 创建新进程了，
但如何在这个新进程中运行一个程序呢？

### 示例4：ex4.c —— 用可执行文件替换调用进程

shell 是如何运行一个程序的？例如：

```bash
$ echo a b c
```

程序存储在一个文件中，包含指令和初始内存数据，由编译器和链接器生成。
因此存在一个名为 echo 的文件，其中包含程序指令。
在你的计算机上可以执行：`ls -l /bin/echo`

ex4.c

exec() 会用可执行文件替换当前进程，
丢弃原有的指令和数据内存，
从文件中加载指令和初始内存，
并保留文件描述符。

```bash
$ ex4
```


`exec(文件名, 参数数组)`

参数数组包含命令行参数；exec 会将这些参数传递给 main() 函数。

`cat user/echo.c`

echo.c 展示了程序如何读取其命令行参数。
如果 exec() 成功执行，则不会返回！

### 示例5：ex5.c —— 使用 fork() 创建新进程，再通过 exec() 执行程序

shell 不能直接调用 exec()！
因为一旦调用 exec()，shell 就不再运行，
也就无法接受多个命令。
ex5.c 展示了 shell 如何处理这个问题：

先使用 fork() 创建子进程，
子进程调用 exec()，
父进程则通过 wait() 等待子进程结束。

```bash
$ ex5
```

shell 对你输入的每个命令都会执行一次 fork/exec/wait 操作。
wait() 完成后，shell 才显示下一个提示符。

exit(status) -> wait(&status)

允许子进程向父进程返回 32 位的信息。
状态码约定：0 表示成功，1 表示命令执行出错。

!!! note "注意："

    fork() 会复制内存，但 exec() 会丢弃复制后的内存，


这看起来似乎有些浪费。
在“写时复制”实验中，你将消除这种浪费。

### 示例6：ex6.c —— 重定向命令的输出

shell 在这种情况下是如何处理的？

```bash
$ echo hello > out
```

答案：fork，子进程修改文件描述符1，然后执行echo命令

```bash
$ ex6
$ cat out
```

!!! note "注意："

    open() 总是选择最低的未使用文件描述符；
    由于close(1)，所以选中了1。


!!! note "注意："

    exec会保留文件描述符。

fork、文件描述符和exec协同工作，实现了输入输出重定向。

分开进行fork再exec，使得子进程有机会在exec放弃控制权之前修改文件描述符，同时又不会影响父进程的文件描述符。

文件描述符提供了间接性：

命令只需使用文件描述符0和1，无需知道它们实际指向何处。

因此，只有shell了解输入输出重定向，而每个程序不必知晓。

**值得思考设计决策背后的 "为什么"：**

- 为什么要采用这些I/O和进程抽象？为什么不采用其他方式？

- 为什么要提供文件系统？为什么不直接让程序按自己的方式使用磁盘？

- 为什么要用文件描述符（FD）？为什么不把文件名传给write()？

- 为什么不将fork()和exec()合并？


UNIX运行良好，但还有其他优秀的设计方案！

### 示例：ex8.c —— 进程间通信

管道与 fork() 结合，实现父子进程之间的通信。
创建一个管道，
执行 fork()，
父进程向其中一个管道文件描述符写入数据，
子进程从另一个管道文件描述符读取数据。

```bash
$ ex8
```

shell 使用 pipe()、fork() 和 exec() 构建管道。
管道是一种独立的抽象机制，但能很好地 配合使用。
